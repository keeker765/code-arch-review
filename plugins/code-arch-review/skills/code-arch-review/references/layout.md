# 目录与拆分

## 硬规矩

| 规矩 | 阈值 | 依据 |
|---|---|---|
| 一层平铺的模块数 | ≤ 7 | 用户 2026-09-08 定,比业界常见的 12 更严:**一眼扫不完等于没有导航** |
| 单文件行数 | ≤ 500(新代码) | 闸的 `long-module`。存量 1000 行是红线,**新写或重构按 500** |
| 同名模块 | 不许出现在两个目录 | 报错栈、编辑器标签、import 语句里都分不清是哪一个 |
| 函数行数 | ≤ 60 | 闸的 `long-function` |

**拆分触发条件(任一即拆)**:模块 > 500 行;一个文件里有 ≥3 个不同职责;
或你开始想写 `# --- XXX SECTION ---` 分隔注释 —— **想加分隔线的那一刻,它就该是两个文件。**

**不拆的理由**:触发拆分的是「**找不到**」,不是「文件多」。7 个文件平铺一眼就找到,
这时加目录是净亏损。

## 分组轴

**按「一起改的东西」分,不按文件类型分。** `models.py / services.py / routes.py`
这种按技术层切的扁平法,小项目好看,规模上去不 scale。

点名的反模式:`utils.py` / `helpers.py` / `misc.py` / `common/` —— 杂物堆。
有领域含义的函数回到它的领域里去。

**依赖必须单向**:`entrypoints → services → domain → shared`。循环 import 永远是结构问题,
不是 import 顺序问题;修法是抽出第三个模块,不是延迟 import。

## 层数

| 模块数 | 层数 |
|---|---|
| ≤ 7 | 1 层,平铺就对 |
| ≤ 49 | 2 层 |
| > 49 | 3 层 |

数量只决定「该不该分」;**能不能分**看这条:

> **加一层的必要条件:你能用一句话说出这个目录不许 import 谁。**

- ✅ `fast/fees/` —— "fees 不许 import position 和 account"。这句话能写进 `__init__.py`,也能写成测试。
- ❌ `common/` / `utils/` —— 说不出禁区,因为它谁都能 import、谁都 import 它。
  **这种目录是装饰不是边界。**

**第 3 层的唯一正当理由**:某个第 2 层的组自己又超过 7 个,且组内有可命名的单向切分。
第 3 层还不够,**不是加第 4 层,是拆成平级的独立包** —— 4 层意味着每次深层 import
要执行一路 `__init__.py`,而且到那一步问题已经不是目录,是这个包承担了两个包的职责。

**反向自检**:加完一层后问「新来的人找一个文件,是变快了还是变慢了?」
收益是「我知道该去哪个目录找」,代价是「我得先知道有哪些目录」。

## 落地动作

- **`__init__.py` 只放 re-export 和导览,不放逻辑** —— 逻辑会让每次深层 import 都执行一路 `__init__`。
  新包先写导览:为什么存在 / 五个角色分组 / 口径边界。
- **拆分是平移 + `__init__` re-export**,调用方 import 不变。
  **不许"顺手重构逻辑"** —— 搬家和改装混在一起,出问题时分不清是谁干的。
- 一次一个组,每组跟一次全量测试。
- 测试目录镜像源码目录 —— **这是团队约定,不是通行规则,闸不查它**。
  2026-10-15 核对:单元/集成分目录、测试目录镜像源码、`tests/` 要不要 `__init__.py`
  这三条**都没有权威出处**,而官方文档在最后一条上自相矛盾;实测 flask / httpx /
  requests / attrs / click / werkzeug / black 全用平铺的 `tests/`,只有 celery、
  ansible、sentry 这类才分层。**别拿它当验收标准**——照它拦会把大批合法项目判成违规。
- **分组不能靠猜名字**:落地前先跑包内 import 图确认没有反向边。
  **有反向边说明分组错了,改分组,不要改 import。**

## 一次实际演算(套用方法的范例)

来源仓库的 `onchain_lp/`:顶层 42 个模块平铺,7461 行,外加 `ledger.py` / `contracts.py`
各有两份重名。

每层封顶 7 ⇒ **至少 6 组,每组 ≤ 7,刚好用满 2 层**。顶层本身也要 ≤ 7,
所以现有的 `fast/` `hosts/` `research/` `rules/` **必须并进这 7 个组里**,
不能在它们旁边再摆 6 个新目录(那样顶层就是 10 个,还是扫不完)。

领域轴(⚠️ 按文件名拟的,**落地前必须用真实 import 图核验**):
链上原语 · 数据接入 · 决策 · 执行与账户 · 评估 · 快评 · 编排入口。

换到别的项目照这套算术走,但领域轴换成你自己的 ——
`chain ← feed ← decide ← execute ← evaluate ← run` 是那个仓库的轴,不是通用的。
