# 注释写在哪、写什么

## 🔴 if / raise:一个条件一行,注释一行(用户 2026-09-08 定)

函数内**全部** `if` / `elif`,包括顶层守卫:

1. **一个条件占一行** —— `a and b` 挤在同一行算违规,按 `and`/`or` 摊平后逐个数。
2. **每个条件上面一行独立注释** —— 行尾注释不算。写清:判什么、判不过会怎样。

```python
# ✅
if (
    # 几何缺失 ⇒ 开不出仓,不是零收益
    row.geometry_status != 'ok'
    # 热度出带 ⇒ 入场即触发出场,白付两条腿 gas
    or not config.heat_low <= row.heat_1h <= config.heat_high
):
    continue

# ❌ 挤行
if row.geometry_status != 'ok' or row.fee_pips < config.min_fee_pips:
```

`raise` 同理:上面一行独立注释,写明什么前提被破坏、调用方该怎么改。
异常消息面向运行时,注释面向读代码的人。

## 🔴 扁平代码 / 循环

**扁平代码**:每个语义段前面一行独立注释。闸按「连续 > 5 条语句无注释」报。

**循环**的注释要写三件事:**遍历什么、每轮做什么、为什么必须循环**(为什么不能向量化)。

```python
# 逐行累加:行与行之间有 carry 依赖,顺序是语义,向量化会改变结果
for row in rows:
    carry = carry + row.fee_raw
```

## 🔴 变量与字段:名字说「是什么」,注释说「怎么来的」

- **字段**:每个字段上方(或行尾)写形状、单位、口径、取值范围。字段是唯一被认可的
  行尾注释场景。
  ```python
  # 报价腿余额,raw 整数(未除 decimals);None = 该时点无法估值,不是 0。
  quote_raw: int | None
  ```
- **算出来的变量**:右侧是运算 / 调用 / 三元 / 比较时,上方要有注释。
  字面量赋值不用(`limit = 8` 没什么可解释的)。
- **算式 return**:`return <算式>` 上方写返回值口径 —— 单位、正负号、边界。
  `return x` / `return None` / `return self.foo` 不要求。

**位置边界**:注释必须紧贴被解释的那一行。写在 `try:` / `if:` 上方只解释了那个块,
不解释块内第一条语句;闸按行号相邻判。

```python
# ❌ try 上方的注释不算给里面的赋值
try:
    balance = settle(order, balance)

# ✅
try:
    # 扣款后的余额;失败时保持原值
    balance = settle(order, balance)
```

**边界**:这三条防的是「读者得去猜」。注释重复代码等于没写 ——
`# 把 a 和 b 相加` 能过闸,过不了 review。

## 🔴 踩过的坑当场写

**修好之前写,修好之后也不要删。** 注释是坑的墓碑,不是待办事项。
写三件:**症状 → 成因 → 为什么这个写法能挡住**。

```python
# float(H) + L 在超过 2^53 时会差 1 ULP,而 L/(H+L) 的分母正好落在那个量级,
# 于是宽区间的费用分配和窄区间不一致。必须整数相加再 true divide。
share = L / (H + L)
```

写的是**这段代码本身的坑**,不是流水账。「我试了 A 不行改用 B」进记忆;
「为什么不能用 A」进代码。

## 🔴 删空行 = 作弊

空行是段落。实测抓到过把 PEP 8 空行删光、让 500 行闸失效的交法:
`fees/cache.py` 500 行 0 空行,而正常文件是 9–10%。顶层定义之间 2 个空行,
类内方法 1 个;定义上方紧贴的注释块算定义的一部分,空行在注释块之前。
